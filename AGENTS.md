# Repository Instructions

## Scope

This repository contains a Raycast extension, a native macOS Bluetooth helper, and a native iPhone app for IKEA IDÅSEN desks.

Read `docs/ARCHITECTURE.md` before changing component boundaries. Read `docs/SAFETY.md` before changing movement behavior.

## Product naming

The public extension name is **Standing Desk**. Use **IKEA IDÅSEN** only for verified hardware compatibility. Do not rename the extension to IDÅSEN Desk.

## Safety rules

- Treat `move`, `nudge`, Sit, Stand, Raise, and Lower as physical actions.
- Do not run a physical movement during tests without explicit user authorization.
- A status-only desk read is allowed when live verification is requested.
- Keep Stop available during every movement workflow.
- Preserve the 45-second timeout, stall detection, target bounds, and movement lock.
- Preserve latest-request-wins handoff. Atomically replace `stop-request` with a unique identifier before each movement or Stop action; never clear it.
- Keep iPhone movement foreground-only. Preserve lifecycle Stop, serialized control writes, setup acknowledgements, and final-Stop priority.
- Keep the iPhone safety acknowledgement as a one-time app-data-lifetime prompt. Do not revoke it for selection or settings changes.
- Never weaken a safety guard without an explicit requirement and a focused test.

## Source boundaries

- `src/` contains Raycast commands, settings, persistence, and native-process orchestration.
- `native/StandingDeskCore.swift` is the shared source of truth for protocol constants, conversions, configuration validation, and movement evaluation.
- `native/DeskBLE.swift` owns the macOS helper's CoreBluetooth and process lifecycle.
- `ios/StandingDesk/` contains the SwiftUI app, iPhone persistence, and in-process CoreBluetooth controller.
- `ios/StandingDeskTests/` contains disconnected iOS policy and persistence tests.
- `assets/deskctl` is generated by `scripts/build-native.sh` and must stay synchronized with the Swift source.
- `docs/BLUETOOTH.md` documents the protocol constants and conversions.

Do not edit `assets/deskctl` directly. Rebuild it after every Swift change.

## Required verification

Run these checks after code or build changes:

```sh
npm run lint
npm run typecheck
npm test
npm run build
scripts/verify-ios.sh
```

Run `git diff --check` before committing.

Use `./assets/deskctl status ...` only for status-level live verification. State clearly when physical movement was not tested.

## GitHub releases

- `VERSION` is the release source of truth. Push the matching `v<VERSION>` tag to run `.github/workflows/release.yml`.
- Package only a clean worktree. The source archive comes from `HEAD`, so this prevents source and bundle assets from diverging.

## Compatibility

Keep `@raycast/api` compatible with the installed stable Raycast application. A major API update can target a different Raycast runtime.

Build the native helper for both `arm64` and `x86_64`. Preserve its embedded Bluetooth usage description and ad-hoc signature.

Keep the iPhone deployment target at iOS 17 or later. Do not add the CoreBluetooth background mode.

## Changes and documentation

- Update the relevant document when behavior, configuration, protocol, or verification changes.
- Keep command names in `package.json` synchronized with `src/` entry points.
- Add focused tests for pure TypeScript logic and native protocol conversions.
- Preserve user data stored through Raycast `LocalStorage` unless migration is part of the request.
- Preserve iPhone data stored through `UserDefaults`. Decode stored settings field-by-field so one malformed or missing field does not forget the selected desk.

Do not include credentials, device identifiers, or local support paths in commits or logs.
